# Task 04 handoff: PCB, validation, and manufacturing candidate

## Result

Task 04 now provides seven Rust crates covering typed PCB geometry, the physical board model, deterministic placement, routing adapters, native DRC/DFM, KiCad PCB projection, and immutable manufacturing-candidate export/verification.

The checked-in golden flow consumes `logical-netlist-v0`, creates a 60 x 40 mm two-layer board, preserves the locked connector and mounting holes, runs deterministic placement and routing, produces a zero-error native DRC report with explicit coverage gaps, projects a parseable `.kicad_pcb`, and exports a hash-bound manufacturing candidate. The independent package verifier reports `validManufacturingCandidate: true`.

This is not a Production Release. The module intentionally exposes no `production_release` or `release_revoke` tool, never uploads to a factory, and reports G6/G7, factory DFM, prototype testing, named signoff, and signed release-manifest gaps.

## What is algorithmic and what is a fixture

- `baseline-grid-cluster-v1` is a real deterministic baseline placement heuristic. It orders fixed/locked and role-priority footprints, supports local selection/region placement, records seed/input hash/cost/metrics, and blocks hard-conflict candidates. It is not a commercial global optimizer.
- `manhattan-reference-router-v1` is a real deterministic Manhattan baseline router for ordinary Phase 0 nets. It applies net priority and profile width/via classes. It does not claim differential-pair, length matching, controlled impedance, SI, or push-and-shove support.
- `deterministic-fake-router-v1` is test-only and exercises success, unrouted, violating, canceled, crashed, and unknown terminal states.
- `logical-netlist-v0/golden-board.json` is the frozen integration fixture until task 03 provides the same versioned contract through its public API.

## Validation state

- Native DRC: executed; 12 rule/check families; golden report has zero errors and retains explicit SI/PI/thermal/EMC/high-speed gaps.
- KiCad reference DRC/export: not executed. `kicad-cli` is absent; expected reference version is KiCad 10.0.5, and no binary hash is available to pin.
- Freerouting: not executed. No configured binary is present, so version/hash/arguments are intentionally not fabricated. Java 17 is present but is not evidence that Freerouting ran.
- Manufacturing readback: executed using the bounded independent verifier. Every manifest entry was hash-checked and the required Gerber, Gerber Job, Excellon, IPC-356, BOM, CPL, KiCad S-expression, and native STEP-candidate structures were parsed and cross-checked. No third-party/reference parser was available in this environment.

## Output provenance

All checked-in Gerber, drill, IPC-356, BOM, CPL, assembly SVG, STEP candidate, `.kicad_pcb`, object map, coverage, DRC, revision, and manifest files were generated by task 04's native exporters from one candidate revision. None was generated by a real KiCad process. `reports/reference-gates.json` records that distinction.

## Integration order

1. Task 03 should supply `logical-netlist-v0` through a stable public adapter with exact footprint and pad mapping. Task 04 must continue to reject missing maps.
2. Task 02 should bind `register_physical_module()` descriptors to the kernel-owned execution/transaction registry. Task 04 already reuses task 02's `ToolDescriptor`, `Permission`, `Effect`, and JDP protocol version, but must not commit the project pointer itself.
3. Task 05 should adapt the board display list, hit-test, snap, cross-probe, preview, and semantic edit candidate APIs into the native workbench. Task 05 must submit commits through the kernel transaction service.
