# Jingwei-Agent 产品需求文档

> 版本：0.5  
> 日期：2026-08-19  
> 状态：待评审  
> 本文中的“必须”表示 MVP 或生产安全约束；“应”表示目标能力；“可”表示后续增强。

## 1. 产品定义

Jingwei-Agent 面向电子产品团队，把自然语言、结构化约束和参考资料转化为可继续编辑的原理图与 PCB
工程，并交付经过机器检查、可追溯的制造数据包。产品自身包含 AI 原生 EDA 设计内核，不依赖 AI 模拟鼠标
操作传统 EDA 才能工作。

核心价值不是减少鼠标操作，而是把需求、器件、库、网络、布局、布线、验证和制造信息放在同一条可审计
链路中，降低漏项、错封装、错引脚、库存失效、版本错配和“Gerber 能打开但不能生产”的风险。

## 2. 目标用户

### 2.1 主要用户

- 产品/方案工程师：从功能、成本、尺寸和交付周期提出需求；
- 硬件工程师：审查器件、原理图、约束、布局布线和生产包；
- PCB 工程师：修订叠层、规则、布局、布线与 DFM 问题；
- 采购/供应链：确认制造商料号、库存、生命周期、交期和替代料；
- 制造/测试工程师：消费 Gerber、钻孔、BOM、CPL、装配图、测试点和说明。

### 2.2 不应假设的用户能力

产品允许用户只输入一句需求，但不能假设这句话已经包含所有工程条件。缺少会改变安全性、拓扑或关键器件
的条件时，Agent 必须提出少量、明确、可解释的补充问题；低风险偏好可使用透明默认值并允许后续修改。

## 3. 成功标准

### 3.1 用户成功

- 用户可从需求建立一个版本化项目，不需要手工拼接多个 EDA 辅助脚本；
- 每个关键器件都有选型原因、来源、精确 MPN、封装和替代策略；
- 每个自动生成/下载的符号和封装都可追溯到数据手册或有许可证的库来源；
- 用户能在 Jingwei 原生工作台或兼容 EDA 中继续编辑源工程，而不是只拿到不可维护的图片或 Gerber；
- 任何自动检查失败都定位到对象、规则、证据和建议修复，不用猜测模型内部状态；
- 制造包与对应源工程、BOM、规则配置和验证报告完全一致。

### 3.2 产品成功指标

首个受控板型的目标指标：

- 需求到原理图初稿的任务完成率不低于 90%；
- 官方/已批准器件库直接复用率不低于 80%；
- 自动生成库的引脚/焊盘映射在黄金数据集上达到 100% 一致；
- 进入候选发布阶段的项目 ERC error、DRC error、未连接网络均为 0；
- 制造包清单、哈希和源版本一致性检查通过率 100%；
- 同一输入、同一工具链锁定版本与随机种子可复现相同的确定性检查结果；
- Agent、GUI 和 CLI 对同一结构化 patch 产生相同的 JIR revision；
- 同一用户输入、工具调用和审批在重启恢复后不得重复产生副作用；断线 UI 可从事件 sequence 恢复一致状态；
- 设计查询和局部修改不要求模型加载或重写整个板卡文件；
- 严重问题不得通过模型解释、自动豁免或重试被隐藏。

这些指标不等于量产良率承诺。量产良率还取决于工艺、器件批次、装配、测试和实际使用环境。

## 4. 范围

### 4.1 MVP 支持范围

- 低压直流，默认不高于 24 VDC；
- 常规 2 层/4 层刚性 FR-4；
- 线宽、间距、孔径、阻焊桥等均在常规板厂标准能力内；
- QFN/QFP/SOIC/SOT、常规连接器与 0402 及以上被动器件；
- MCU 或认证模组、GPIO、I2C、SPI、UART、USB 2.0 低/全速、低速 CAN/RS-485；
- LDO、常见低功率 Buck/Boost 参考设计；
- LED、按键、继电器/小功率 MOS 管驱动、常见传感器接口；
- 单板、单一主装配变体，允许 DNP；
- 常规 Gerber/Excellon、BOM、CPL/PnP、PDF 原理图/装配图、STEP、制造说明；
- Jingwei 原生 JDL/JIR 工程作为交付必选项；MVP 同时输出 KiCad 兼容工程。

### 4.2 可分析但 MVP 不自动发布

- 超过 24 VDC、电池大电流、隔离电源、市电或高压；
- 射频天线、微波、受控阻抗高速串行、DDR、MIPI、PCIe、千兆及以上 SERDES；
- 大功率、电机逆变、精密模拟、低噪声测量；
- BGA、HDI、盲埋孔、刚挠结合、金属基板、陶瓷基板；
- 汽车、医疗、航空航天、功能安全或法规强约束产品；
- 需要安规间距、爬电距离、EMC 认证或本质安全认证的设计。

系统可以提供概念方案和风险清单，但必须阻止“生产发布”，直到对应专业规则、仿真、审查与签核能力被实现。

### 4.3 明确不做

- 不根据模糊图片臆造精确封装尺寸或引脚；
- 不抓取或重新分发没有授权的商业元器件库；
- 不把搜索摘要当作数据手册原文；
- 不在缺少制造商 profile 时自动选择“看起来能做”的工艺；
- 不在没有样板与测试证据时把项目标记为量产；
- 不替代法规认证机构、制造商工程审核或具名工程师签核。

## 5. 端到端用户流程

### 5.1 建立需求合同

1. 用户输入自然语言、参考文件、尺寸/接口草图、目标成本和数量；
2. Agent 提取硬约束、软偏好、未知项和冲突；
3. 对安全、拓扑、机械、供电、关键接口和制造方式的未知项提问；
4. 生成可编辑的 `DesignIntent`，用户确认后建立需求基线；
5. 后续每次需求变更都生成影响分析，不静默覆盖。

需求、GUI 编辑、Agent 工具调用和外部 EDA 导入最终都编译为 JDP transaction，并生成新的 JIR revision。

### 5.2 方案与器件选型

1. 分解功能模块和电源树；
2. 为关键 IC 建立候选集合；
3. 先应用绝对额定值、接口、封装、温度、供货和法规等硬过滤；
4. 再按成本、库存、生命周期、面积、功耗、生态和风险评分；
5. 展示首选、备选和淘汰原因；
6. 用户确认关键器件或接受项目定义的自动选择策略。

### 5.3 库解析与生成

1. 按项目锁定库、Jingwei 组织库、官方 KiCad 库、批准的第三方库顺序查找；
2. 校验精确 MPN、封装名、引脚数、焊盘号、单位和极性；
3. 缺库时，从制造商数据手册封装图和引脚表生成候选符号/封装；
4. 对符号引脚、封装焊盘和 3D 模型建立映射；
5. 通过几何、命名、引脚映射和渲染检查；
6. 新库进入项目私有库并记录 provenance，未经批准不写入全局共享库。

### 5.4 原理图生成

1. 按功能模块建立层次页；
2. 放置器件、网络标签、电源、去耦、保护、测试点和连接器；
3. 为关键电路附上数据手册章节、参考设计和计算依据；
4. 执行 ERC、未连接检查、引脚方向检查和自定义电气规则；
5. 对每条告警修复或形成具名、带理由、带过期条件的豁免；
6. 在原生工作台打开可交互原理图，支持层次导航、网络追踪、finding 定位和语义差异；
7. 用户可直接移动/放置器件、修改属性、编辑连接/标签并锁定人工确认对象；
8. 人工编辑提交为新 JDP revision，增量重跑受影响检查，并可继续交给 AI 局部修改。

### 5.5 PCB 约束、布局与布线

1. 用户或机械文件定义板框、安装孔、连接器、禁布区和高度限制；
2. 选择制造商 profile、叠层、铜厚、表面处理、最小规则；
3. 从接口/电源/关键器件到普通器件分阶段布局；
4. 先布关键网络、电源回路、差分/长度约束网络，再处理普通网络；
5. 自动布线器只生成 JIR 候选 revision；必须执行 Jingwei 原生检查，并投影到 KiCad 做首期独立 DRC；
6. 完成回流路径、过孔、电流密度、热、丝印、可装配性和测试点检查；
7. 在原生工作台打开交互式 PCB，支持层/网络/finding/3D 联动和候选差异；
8. 用户可移动/锁定 footprint，编辑板框、区域、track、via、zone、丝印和普通约束；
9. 用户可框选网络/区域交给 AI 局部重新布局布线，未选中和锁定对象默认保持不变；
10. 所有布局/布线变更都能追溯到人工/AI/solver、约束和算法版本。

### 5.6 制造与生产发布

1. 从同一已锁定 revision 导出全部制造和装配文件；
2. 执行 Gerber/钻孔解析、层集、网表一致性、BOM/CPL 对应和坐标/旋转检查；
3. 生成制造包 manifest、文件哈希、工具版本、规则版本和签核记录；
4. 通过制造商 DFM 并处理工程问询；
5. 样板完成上电、功能和必要的可靠性验证；
6. 由指定角色签核后提升为 Production Release；
7. 任何源设计、BOM、工艺或替代料变更都会使原生产签核失效或触发影响复核。

## 7. 非功能需求

### 7.1 正确性与可追溯性

- 所有关键设计结论必须链接到需求、数据手册、规则或人工决策；
- 设计对象使用稳定 ID，不以屏幕坐标或自然语言名称作为唯一身份；
- 所有生成器和验证器必须记录版本、配置、输入哈希和输出哈希；
- 模型不得直接修改“已发布”revision，只能创建新变更集；
- 任何自动豁免都默认禁止。
- JDL、GUI、Agent 与导入器不得绕过 JDP 直接写 current JIR snapshot。

### 7.2 可复现性

- 锁定 JIR schema、JDL/JDP、Jingwei 内核、KiCad reference backend、库、求解器、制造商 profile 和依赖版本；
- 随机算法记录 seed；
- 外部价格/库存视为带时间戳快照，不能要求未来完全重现；
- 生产包必须能从对应源 revision 重新生成并通过哈希/语义比较。

### 7.3 性能目标

以 MVP 黄金板为基准：

- 需求编译与初次追问在 30 秒内给出；
- 本地库查询在 3 秒内返回；
- ERC/DRC 在 60 秒内完成；
- 常规板自动布局单候选在 5 分钟内完成；
- 自动布线允许按 5/15/60 分钟预算生成候选并可取消；
- 取消后不得残留未知写入，不能确认回滚时进入安全隔离。

### 7.4 安全与隐私

- 默认本地处理设计文件和私有库；
- 任何上传云端模型、路由或 DFM 服务的行为必须显示目标、内容和授权；
- API 密钥使用操作系统安全存储，不进入工程、日志或制造包；
- 外部数据和库文件按不可信输入解析；
- 项目级权限约束不得被子 Agent、脚本或外部插件绕过。
- MCP/tool metadata、外部资料和 provider 输出只作为不可信输入；执行权限由 runtime policy 与 daemon 独立复核。

### 7.5 可维护性

- EDA 核心逻辑与 UI、LLM 提示、供应商适配器分离；
- Agent runtime 与 EDA daemon 分离：前者可保持 TypeScript/Bun 以复用成熟能力，后者以 Rust 作为设计可信计算基；
- 原生设计通过 JIR/JDP 事务写入；外部格式使用 AST/adapter 和 round-trip 校验，不进行脆弱的文本拼接；
- 先稳定 JIR/JDP 语义，再冻结 JDL 表面语法；schema 演进必须提供迁移器和黄金回归；
- 制造商规则、器件源和路由器均通过版本化适配器扩展；
- 所有生产门禁必须有自动化回归和失败样例。

## 8. 量产定义

项目状态从低到高为：

1. `draft`：模型/用户正在编辑；
2. `candidate`：JIR 源 revision 完整，可执行原生和 reference backend 检查；
3. `engineering-verified`：自动检查通过并完成工程师设计审查；
4. `prototype-verified`：样板制造、上电和计划内测试通过；
5. `production-released`：制造商 DFM、供应链、测试与具名签核全部满足。

只有第 5 级可对外称为生产发布。Gerber 导出成功最多证明生成了制造文件，不能单独提升项目状态。
